# Эскалация в разработку

Регламент взаимодействия с разработкой описывает порядок передачи задач на 3-ю линию.

## Чек-лист

- Обязательное заполнение анкеты.
- Приложение логов и результатов SQL-проверок (см. [проверку конфигурации](/egisz/troubleshooting/configuration-check)).
- Указаны каналы коммуникации и текущий статус обращения.

## Обязательные данные

```text
Клиника:
Версия МИС:
СЭМД:
Редакция:
PROTOCOLID / идентификатор документа:
Статус:
Ожидаемое поведение:
Фактическое поведение:
Шаги воспроизведения:
Полный текст ошибки:
Диагностика:
Логи:
Что уже проверено:
Влияние на клиента:
```

## Если проверка не пройдена

Обращение не передаётся в разработку без заполненной анкеты, логов и результатов SQL-проверок.

## Результат

Дефект принят в разработку с полным набором данных, достаточным для воспроизведения без дополнительных запросов.
