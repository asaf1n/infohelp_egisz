# Настройки

# Общие настройки МИС

Реквизиты заполняют сотрудники медицинской организации. Значения переносятся из ФРМО и ФРМР без начальных и конечных пробелов и нечитаемых символов.

> Расхождение реквизитов организации, структурного подразделения или медицинского работника с ФРМО и ФРМР приводит к отказу в регистрации.
> 

### Реквизиты юридического лица

`Справочники` → `Организации` → `Реквизиты клиники`

| **Поле** | **Значение** |
| --- | --- |
| ОГРН, ИНН | Реквизиты по ЕГРЮЛ |
| Юридический адрес | Выбор по ФИАС |
| Фактический адрес | Выбор по ФИАС |
| Телефон организации | Контактный телефон юридического лица |
| Федеральный код МО (OID) | Значение из ФРМО, проверяется по справочнику ФНСИ 1.2.643.5.1.13.13.11.1461 |
| Территория | Территория расположения организации |
| Сведения о лицензии | Номер и реквизиты лицензии на медицинскую деятельность |

### Реквизиты финподразделений

`Справочники` → `Структура организации` → `Финподразделения, кассы, реквизиты клиники, настройки`

Для каждого финподразделения, в котором создаются приёмы, заполняются «Федеральный код подразделения МО (OID)» и «Федеральное наименование подразделения МО». OID финподразделения МИС соответствует OID структурного подразделения МО НСИ.

### Медпрофили (Отделения)

`Справочники` → `Структура организации` → `Медпрофили`

Для каждого отделения, участвующего в обмене, на вкладке `Общие` заполняются «Медицинская специальность медпрофиля» и «Профиль медицинской помощи по ФедНСИ». Список специализаций определяет состав значений, доступных для поля «Специальность в отделении» в карточке сотрудника..

### Справочник персонала

`Справочники` → `Справочник персонала`

| **Поле или вкладка** | **Требование** |
| --- | --- |
| Связь с физическим лицом | Карточка связана с физическим лицом, содержащим актуальные ФИО и СНИЛС |
| Должность (справочник) | Значение справочника «Должности» 1.2.643.5.1.13.13.11.1002, соответствующее должности в ФРМР |
| Специальность в отделении | Значение из списка специализаций отделения, с указанием периода действия |
| Сертификаты ЭЦП | Действующий сертификат УКЭП с корректным сроком действия |

После загрузки справочника «Должности» перечень должностей в справочнике персонала обновляется.

### Данные пациентов

`Картотека пациентов` → `Карточка регистрации`

- ФИО, дата рождения.
- Документ, удостоверяющий личность.
- СНИЛС.
- Отметка отказа от передачи данных при необходимости.

### Сопоставление услуг с номенклатурой Минздрава

`Справочники` → `Прейскурант` → `Реквизиты`

Заполняются поля «Код Минздрава» и «Наименование Минздрава» по справочнику ФНСИ 1.2.643.5.1.13.13.11.1070 «Номенклатура медицинских услуг».

### Временная зона

`Справочники` → `Структура организации` → `Филиалы` → `Временная зона (часовой пояс)`

Значение указывается по UTC.

### Медиа-база

`Справочники` → `Структура организации` → `Филиалы` → вкладка `Реквизиты` → `БД подписанных протоколов (медиа-база)`

Расположение медиа-базы указывается для каждого филиала и для центральной базы данных.

### Учёт случаев заболевания

`Права доступа` → `Приём` → `Случаи заболевания. Диагноз`

- «Учёт случаев заболевания»;
- «Постановка основного диагноза через учёт случаев заболевания».

Для стоматологических клиник дополнительно включается `Сервис` → `Настройки` → `Поликлиника` → `Общие` → `Учёт случаев заболевания в стоматологии`.

Медицинские организации, ведущие учёт случаев в упрощённом режиме, применяют автоматическое закрытие случая. Открытие случая выполняется вручную.

### Параметры интеграции

`Сервис` → `Настройки` → `Интеграция`

| **Параметр** | **Значение** |

### Настройки подписи в МИС

`Сервис` → `Подключение оборудования` → `ЭЦП`

Заполняются криптопровайдер и параметры проверки ЭЦП.

`Сервис` → `Специальные настройки` → `Криптография (ЭЦП)` → `Использовать ЭЦП для протоколов истории болезни`

Настройка включается для конкретных типов протоколов или для всех протоколов истории болезни.

### Справочники НСИ

Актуализация справочников выполняется службой SyncServer: список кодов НСИ или профилей загрузки задаётся в `sync.conf`. В филиальной сети загрузка выполняется на центральной базе данных.

Состав загружаемых справочников определяется руководствами по реализации передаваемых видов СЭМД.

## Доверенное подключение между базами

Обращение к филиальным базам выполняется под текущим пользователем без пароля. Правило мэппинга создаётся в BkUtils на всех базах данных, включая медиабазы и базу конфигуратора репликатора.

```sql
CREATE OR ALTER MAPPING ESOE_CLUSTER_AUTH
  USING PLUGIN CLUSTER
  FROM USER CHEA to USER CHEA;
```

Проверка доверенного подключения к текущей базе данных выполняется в BkUtils под пользователем CHEA. Успешным результатом считается выполнение без ошибки.

```sql
execute block
as
declare tmp integer;
begin
  execute statement 'select 1 from rdb$database'
  on external 'localhost:' || rdb$get_context('SYSTEM', 'DB_NAME') as user current_user role current_role password ''
  into tmp;
end
```

# ИЭМК

### Базовая настройка интеграции

Настройка выполняется для каждой медицинской организации и входит в состав работ по подключению к РЭМД. Назначение — передача персональных сведений о пациенте в ГИП при регистрации пациента и при изменении его данных. Сведения из ГИП используются при проверке соответствия пациента на стороне РЭМД.

- Работы в базе данных.
    
    Создание триггеров репликации на таблице журнала обмена `FIR_MC_ARC`:
    
    ```sql
    execute procedure repl$create_triggers('fir_mc_arc', 'iud');
    ```
    
    Для филиальной сети на центральной базе данных дополнительно создаются триггеры журнала изменений:
    
    ```sql
    create or alter trigger REPL$FIR_MC_ARC_AI for FIR_MC_ARC
    active after insert position 0
    AS
    BEGIN
      IF (EXISTS(SELECT * FROM REPL$GETACCESS WHERE REPL$ACCESS = 'REPL')) THEN
      BEGIN
        INSERT INTO REPL$CHANGELOG (TABLENAME, REPLID, REPLGRPID, OP, TOGRPID)
        VALUES ('FIR_MC_ARC', NEW.REPL$ID, NEW.REPL$GRPID, 0, NEW.REPL$GRPID);
      END
    END;
    
    create or alter trigger REPL$FIR_MC_ARC_AU for FIR_MC_ARC
    active after update position 0
    AS
    BEGIN
      IF (EXISTS(SELECT * FROM REPL$GETACCESS WHERE REPL$ACCESS = 'REPL')) THEN
      BEGIN
        INSERT INTO REPL$CHANGELOG (TABLENAME, REPLID, REPLGRPID, OP, TOGRPID)
        VALUES ('FIR_MC_ARC', NEW.REPL$ID, NEW.REPL$GRPID, 1, NEW.REPL$GRPID);
      END
    END;
    
    create or alter trigger REPL$FIR_MC_ARC_AD for FIR_MC_ARC
    active after delete position 0
    AS
    BEGIN
      IF (EXISTS(SELECT * FROM REPL$GETACCESS WHERE REPL$ACCESS = 'REPL')) THEN
      BEGIN
        INSERT INTO REPL$CHANGELOG (TABLENAME, REPLID, REPLGRPID, OP, TOGRPID)
        VALUES ('FIR_MC_ARC', OLD.REPL$ID, OLD.REPL$GRPID, 2, OLD.REPL$GRPID);
      END
    END;
    ```
    

### Передача эпикризов по законченному случаю

Контур дополняется передачей сведений о случаях оказания медицинской помощи при подключении СЭМД 233 и 235.

| **Вид документа** | **Идентификатор типа СЭМД** |
| --- | --- |
| СЭМД 233. Эпикриз по законченному случаю амбулаторный (CDA), редакция 5 | `991010000010468` |
| СЭМД 235. Эпикриз в стационаре выписной (CDA), редакция 6 | `991010000010512` |

При закрытии случая заболевания формируется протокол эпикриза — амбулаторный или стационарный по типу случая. Протокол заполняется данными случая автоматически, минимально необходимый набор сведений покрывается стандартными настройками протокола. После подписания протокола средствами МИС формируется сообщение для сервиса ИЭМК.

`Сервис` → `Настройки` → `Поликлиника` → `История болезни` → `Процессный ввод случая заболевания. Формирование эпикриза`

| **Значение** | **Поведение системы** |
| --- | --- |
| Автоматически | Эпикриз формируется и подписывается при закрытии случая |
| Автоматически без подписи | Эпикриз формируется при закрытии случая, подписание выполняется сотрудником вручную. Применяется при самостоятельном управлении отправкой данных |

Формирование и подписание эпикризов вручную доступно в журнале `Журналы` → `Случаи заболеваний` по праву доступа «Формирование эпикриза ИЭМК из журнала случаев».

Наличие типов протоколов эпикризов проверяется в `Справочники` → `Медицинские справочники` → `Настройка параметров ИБ` после загрузки эталонного пакета настроек.

# РЭМД

Объект передачи — электронные медицинские документы в формате HL7 CDA R2, подписанные УКЭП. Врач оформляет протокол истории болезни и подписывает его УКЭП, МИС формирует СЭМД по структуре руководства по реализации вида СЭМД и передаёт его на регистрацию.

РЭМД проверяет состав и формат сведений и формирует синхронный ответ, затем запрашивает тело документа из МИС, выполняет форматно-логический контроль и проверку подписей. При успешном прохождении проверок документу присваивается регистрационный номер, который поступает в МИС.

Хранение документов ведётся в медицинской организации. РЭМД содержит регистрационные сведения, подписи и ссылку на информационную систему-источник для запроса ЭМД.

На адрес callback-сервиса портал «[Инфоклиника.RU](http://Инфоклиника.RU)» направляет результаты регистрации документов и запросы на передачу файлов ЭМД, хранящихся в медицинской организации. 

- Работы в базе данных.
    
    Скрипты выполняются на базе данных, в которой подписываются протоколы.
    
    Создание триггеров репликации на таблице журнала обмена `FIR_EMD_ARC`, после выполнения процедуры МИС перезапускается:
    
    ```sql
    execute procedure FIR_EMD_REMD_CREATE_TRIGGERS;
    ```
    
    Добавление сервисных записей о базах интеграции:
    
    ```sql
    insert into filial_base (filbaseid, basetype, dbpath, dbipaddr, filial, grpid)
    values (GEN_ID(FILIAL_BASE_GEN,1), 1, 'полный адрес БД, например 192.168.1.254:box', 'IP адрес сервера БД, например 192.168.1.254', 1002, 9924);
    ```
    
    ```sql
    insert into filial_base (filbaseid, basetype, dbpath, dbipaddr, bdate, filial, grpid)
    values (GEN_ID(FILIAL_BASE_GEN,1), 2, 'полный адрес медиа БД, например 192.168.1.254:media', 'IP адрес сервера БД, например 192.168.1.254', '01.01.1900', 1001, 9924);
    ```
    

# Подключение отдельных видов СЭМД

Шаблонные протоколы размещены в группе «СЭМД» протоколов истории болезни.

Перечень видов СЭМД определяется медицинской организацией на основании фактически оказываемых медицинских услуг и внутренних процессов.

### Состав работ

| **Состав** | **Содержание** |
| --- | --- |
| Входит в подключение вида СЭМД | Техническая загрузка СЭМД и связанных справочников НСИ. Демонстрация в интерфейсе МИС шаблонного протокола, требуемых реквизитов и порядка их заполнения. Подписание и отправка одного документа в РЭМД |
| Не входит в подключение вида СЭМД | Настройка прейскуранта. Настройка протоколов медицинской карты |
| Протокол лабораторного исследования | Дополнительно выполняется загрузка предоставленных медицинской организацией сопоставлений параметров рабочего места лаборанта с ФСЛИ, сопоставлений биоматериалов и единиц измерения с ФНСИ, консультирование по указанным справочникам |

### Настройка типа протокола

Для каждого типа протокола, передаваемого в РЭМД:

1. Открыть `Настройки` → `Настройки ИБ` и выбрать тип протокола.
2. В реквизитах протокола установить отметку «Подпись ЭЦП».
3. На вкладке `Профили` добавить интеграционный профиль — вид СЭМД по справочнику ФНСИ 1.2.643.5.1.13.13.11.1520.

Формирование XML выполняется МИС по настройкам типа протокола в соответствии со структурой, заданной руководством по реализации вида СЭМД.

### Дополнение собственных протоколов

1. В группе `Параметр` выбрать «Добавить из другого протокола».
2. В строке `Протокол-источник` выбрать эталонный протокол СЭМД.
3. Нажать «Выделить обязательные». Отображаются поля, необходимые для формирования СЭМД. Строки, выделенные жёлтым цветом, содержат настройки, совпадающие с параметрами протокола медицинской организации.
4. Перенести необходимые параметры или группы параметров.
5. Нажать «Подтвердить».

Для каждого параметра указываются вид параметра, тип параметра и запрос к справочнику, совпадающие со значениями эталонного протокола.

Удаление доступно для параметров, добавленных в протокол медицинской организации. Для собственного параметра, заменяемого параметром эталонного протокола, устанавливается дата окончания действия.

## Особенности филиальной сети

- Скрипты настройки базы данных выполняются на всех базах данных филиалов.
- Настраивается задача репликации таблицы `FIR_EMD_ARC` из центральной базы данных в филиалы.
- Настраивается задача репликации таблицы `FIR_MC_ARC` между центральной базой данных и филиалами.
- В репликацию из центральной базы данных в филиалы добавляются таблицы справочников: `SYNC_REFERENCE`, `SYNC_REFVERSIONS`, `NSI_DIAGRESEARCH`, `WORKPLACEDOCDET`, `FILIAL_BASE`.
