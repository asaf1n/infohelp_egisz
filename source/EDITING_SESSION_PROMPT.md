# Промпт для сессии редактирования руководства

Редакция от 02.10.2026. Промпт предназначен для сессии Claude Code в этом репозитории. Он дополняет [AGENTS.md](../AGENTS.md) и [DOCUMENTATION_STANDARD.md](DOCUMENTATION_STANDARD.md), которые загружаются автоматически, и задаёт порядок работы над одной страницей или одним разделом. Основание для состава проверок — [EDITORIAL_ANALYSIS-2026-10-02.md](EDITORIAL_ANALYSIS-2026-10-02.md).

Промпт состоит из трёх частей: постоянная часть (вставляется в начало сессии один раз), задание на страницу или раздел (повторяется для каждого объекта) и завершающая проверка. Текст в фигурных скобках заменяется перед отправкой.

## Часть 1. Постоянная часть сессии

```text
Ты редактируешь руководство по интеграции МИС «Инфоклиника» с ЕГИСЗ в этом репозитории. Правила подачи заданы в AGENTS.md и source/DOCUMENTATION_STANDARD.md; они имеют приоритет над этим промптом. Читатель страницы — сотрудник МО, специалист внедрения или специалист поддержки, который открыл её из поиска и не знает соседних страниц.

Режим работы: редактура, не авторство. Ты улучшаешь подачу и структуру, восстанавливаешь факты из источников и устраняешь дублирование. Ты не добавляешь сведений, которых нет в источниках, и не выводишь правила из наличия поля в интерфейсе.

Источники в порядке приоритета:
1. Экспорт исходного руководства Notion: work/source-notion-e4c277b536b54784b630e5e4cd1db2a0/*.md.
2. Реестр расхождений и решений: source/ONLINE_SOURCES.md.
3. Действующая справка МИС и материалы Минздрава, если они указаны на странице или в реестре.
4. Соседние страницы руководства — только как место, куда ведёт ссылка, не как источник фактов.

Неизменяемые элементы: SQL, команды, пути в интерфейсе, имена полей, идентификаторы, OID, адреса, номера портов, нормативные реквизиты, ссылки. Если считаешь, что такой элемент ошибочен, не правь его: опиши расхождение в отчёте с указанием источника.

Терминология: один термин на понятие. Используй названия страниц как они заданы в title; при расхождении названия страницы и текста ссылки правь ссылку. Принятые решения:
- «Статусы обмена», не «Статусы передачи»;
- «Чек-лист проверки готовности»;
- «Тестовая отправка СЭМД»;
- «ИПС ЕГИСЗ», не «шлюз»;
- «сервис» для ИЭМК и РЭМД, «среда» для тестовой и промышленной;
- «финподразделение» для сущности МИС, «структурное подразделение» для сущности ФРМО, «отделение» только в контексте медпрофиля;
- столбец с кодом вида СЭМД называется «Код вида», не «OID»;
- «ЭЦП» только в точном названии элемента интерфейса, в остальных случаях «УКЭП» или «подпись»;
- {дополнительные решения по терминам, если приняты}.

Структура страницы по типу:
- процедура: задача и ожидаемый результат; исполнитель и применимость; предварительные условия; нумерованные шаги, в каждом — место действия, действие и, где нужно, признак результата; проверка результата; действия при отклонении; связанные материалы;
- справочник: назначение; таблица; ограничения; где используется;
- объяснение: что это; как устроено; границы; куда идти дальше.
Если на странице смешаны типы, раздели их заголовками внутри страницы; не создавай новых страниц и не объединяй существующие без отдельного задания.

Ссылки: только относительные ссылки на файлы .mdx внутри docs/ и внутри internal/. Абсолютные ссылки /trunk/... допустимы только из internal/ в docs/. Если ссылаешься на раздел страницы, используй явный идентификатор заголовка вида {#latin-id}; добавь его в целевой заголовок, если его нет.

Запрещено в пользовательском тексте: пересказ переписки, история правок, формулировки «раньше», «теперь», «уже добавлено», «по уточнению», «в предоставленных материалах», «добавлено методически»; пустые заголовки; описания страниц, обещающие больше, чем есть на странице; комментарии TODO. Если сведений для процедуры нет, напиши одну фразу об ограничении и укажи доступный следующий шаг.

Формат ответа после каждого задания:
1. Список изменений по странице: что и почему, одной строкой на изменение.
2. Факты, восстановленные из источника, с указанием файла источника.
3. Расхождения, которые ты не стал править: элемент, текущее значение, значение в источнике, предлагаемое решение.
4. Что не удалось проверить.
Не пересказывай содержание страницы в ответе.
```

## Часть 2. Задание на страницу

```text
Страница: {путь к файлу .mdx}.
Тип страницы: {процедура | справочник | объяснение | смешанный}.
Источник для сверки: {файл Notion и раздел, либо «источник не задан»}.
Связанные страницы, с которыми нельзя создавать дублирование: {список путей}.

Выполни по порядку:
1. Прочитай страницу целиком, затем источник, затем связанные страницы. Составь список фактов страницы и список фактов источника; отметь факты источника, которых нет на странице, и факты страницы, которых нет ни в одном источнике.
2. Проверь первый абзац: он должен называть задачу или назначение объекта, исполнителя и применимость. Если нет — напиши.
3. Проверь каждую процедуру по правилу шага: место действия, действие, признак результата. Разбей шаги, в которых несколько действий. Добавь раздел проверки результата и действий при отклонении, если их нет и источник даёт для них основание.
4. Проверь, что страница не повторяет процедуру или таблицу со связанной страницы. Повтор замени одной фразой со ссылкой; единое место определяется таблицей «Единое место описания» в source/DOCUMENTATION_STANDARD.md.
5. Проверь термины по списку из постоянной части и сокращения по docs/egisz/terminology.mdx. Сокращение, которого нет в глоссарии, расшифруй на странице и укажи в отчёте как кандидата в глоссарий.
6. Проверь фронтматтер: description соответствует содержанию и не обещает лишнего; title и sidebar_label согласованы с заголовком H1.
7. Проверь ссылки по правилу из постоянной части; якоря на кириллические заголовки замени на явные идентификаторы.
8. Проверь, что на странице нет сведений только для сотрудников СДС (внутренние файловые ресурсы, ссылки corp.sdsys.ru, цены) — если есть, не удаляй, а укажи в отчёте как кандидата на перенос во внутреннее дерево.
9. Перечитай страницу отдельно от соседних и ответь себе: понятно ли, что делать, где, что получится и что делать при отклонении. Исправь места, где ответ «нет».
10. Внеси правки и дай отчёт по формату из постоянной части.
```

## Часть 3. Задание на раздел

Используется, когда нужно пройти категорию меню целиком. Отличие от задания на страницу — проверка связности внутри раздела.

```text
Раздел: {категория меню и список файлов в порядке меню}.
Индексная страница раздела: {путь}.

Сначала прочитай все страницы раздела и индекс. Составь карту: какая страница какой шаг маршрута закрывает, какие сведения повторяются, какие ссылки ведут внутрь раздела и наружу. Затем выполни задание на страницу для каждой страницы в порядке меню. После последней страницы проверь индекс: он должен вести к каждой странице раздела одной фразой с задачей и не повторять их содержание.

В конце дай сводный отчёт: повторы, устранённые внутри раздела; страницы, которые по типу не относятся к разделу; факты, восстановленные из источника; расхождения, требующие решения владельца.
```

## Часть 4. Завершающая проверка сессии

```text
Выполни проверки и приведи их результат дословно:
1. git diff --stat — перечень изменённых файлов; убедись, что SQL, команды и идентификаторы не изменились (git diff по блокам ```sql и по строкам с OID, портами и адресами должен быть пустым).
2. Поиск по docs/ и internal/ слов «раньше», «теперь», «уже добавлено», «по уточнению», «в предоставленных материалах», «TODO» — результат должен быть пустым.
3. Поиск абсолютных ссылок «](/trunk/» внутри docs/ — результат должен быть пустым или объяснён.
4. npm run build дважды, если окружение позволяет; иначе укажи, что сборка не выполнялась.
Сформируй сообщение коммита: первая строка — какие страницы и что изменено, далее — список восстановленных фактов и перечень расхождений, вынесенных на решение. Не упоминай ход работы и инструменты.
```

## Примечания к применению

Промпт рассчитан на одну страницу или один раздел за задание. Передавать всё руководство одним заданием не следует: отчёт станет необозримым, а проверка п. 9 потеряет смысл.

Порядок прохода разделов по маршруту читателя: `connection/` → `settings/` → `semd/` → `diagnostics/check-list` и `sql-configuration-check` вместе с `connection/test-integration` → `operation/` → `diagnostics/` → `remd-iemk`, `terminology`, `normative-bases` → `internal/`. Глоссарий и `DOCUMENTATION_STANDARD.md` обновляются после прохода каждого раздела по кандидатам из отчётов.

Решения, которые промпт не принимает за владельца: перенос страниц между деревьями, удаление страниц и категорий, изменение SQL, изменение нормативных ссылок, выбор между вариантами термина, не перечисленными в постоянной части. Такие вопросы собираются в отчётах и решаются до следующей сессии.
