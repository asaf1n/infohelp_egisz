Реализация:
По реализации. В  SyncManager.exe  в главном меню появилась новая кнопка "Справочники - Настройка профилей менеджера загрузок". Сам справочник сделан по общим канонам с удобными "плюшками" типа "Раскрыть всё", сплиттерами и пр. В дереве профилей можно мышкой перетаскивать профили, чтобы сформировать древовидную структуру.
Переменная для  SyncServer  названа  syncprofiles , можно задать в конфиге или в строке запуска. Можно задать и ид, и текстовые идентификаторы одновременно. Поиск идет рекурсивно по всем профилям-ХП-дет.таблицам с учетом уникальности справочников, т.е. справочники не будут дублироваться в финальном списке.

¶
Описание  ¶
Справочник профилей для модуля sync manager по аналогии с генератором отчётов.
Возможность указать список идентификаторов профилей конфигурационном файле службы
автоматически грузить справочники в т.ч. на основе профиля
Настройка справочника профилей:
возможность ручного включения справочников в профиль
возможность динамического получения состава справочников вызовом ХП
Создание ХП, которая:
использует логику из  #78232  для получения СЭМД
наследует справочники НСИ, использующие этот СЭМД
возвращает массив ID справочников из таблиц  NSI
Создание профиля, ссылающегося на эту процедуру, распространение его в обновлениях
todo:
возможность указать интеграционный профиль для профиля загрузки
интерфейс формы настройки
Описание
Реализация
1. Создать таблицы профилей менеджера синхронизации SYNC_PROFILE, …
2. Реализовать ХП для определения состава справочников профиля
3. Реализовать форму настройки профилей
4. Добавить поддержку параметра для сервиса Sync
Реализация  ¶
1. Создать таблицы профилей менеджера синхронизации SYNC_PROFILE, SYNC_PROFILE_LINKS  ¶

SYNCPROFIDENT  TTEXT64  Текстовый идентификатор профиля менеджера загрузок

2. Реализовать ХП для определения состава справочников профиля  ¶
Хранимая процедура SYNC_PROFILE_GET_DEFAULT
Входящие параметры
Наименование    Тип данных    Комментарий
recid  TBIGCODE = null  Идентификатор записи сущности
rectype  TICODE = null  Идентификатор сущности RECTYPES.RECTYPE
Исходящие параметры
Наименование    Тип данных    Комментарий
ERROR_CODE  TICODE  Код ошибки
ERROR_TEXT  TTEXT1024  Текст ошибки
CHECK_CODE  TICODE  Код контроля ввода данных
CHECK_TEXT  TTEXT1024  Текст сообщения контроля ввода данных
SYNCREFID  TBIGCODE  Идентификатор справочника  SYNC_REFERENCE.SYNCREFID
Алгоритм:
2.1. При вызове SYNC_PROFILE_GET_DEFAULT с  recid = null, rectype = null , вернуть справочники, используемые в протоколах за последние 30 дней
Открыть
with  protocol_list  as
(
select   distinct  protocolid
from  treatplacesigndet tsd
left   join  treatplacesign ts  on  ts . tpsignid  =  tsd . tpsignid
left   join  dicinfo d  on  d . dicid  =  tsd . recid  and  refid  =   -  508   and  d . rekvint1  in   (  2  ,  5  ,  7  ,  14  )
where  tsd . rectype  =   97
and  tsd . modifydate  >   current_date   -   30
and  ts . tpsignid  >   0   and  d . dicid  >   0
)
,  placeid_list  as
(
select   distinct  placeid
from  protocol_list p
left   join  treatplace tp  on  tp . protocolid  =  p . protocolid
)
,  refid_list  as
(
select   distinct  gp . reftodict refid
from  placeid_list p
left   join  workplacedoclinks wpl  on  p . placeid  =  wpl . placeid
left   join  groupsdictlinks gdl  on  wpl . groupid  =  gdl . groupid
left   join  groupsparams gp  on  gdl . codeparams  =  gp . codeparams
where  reftodict  is   not   null
)
select   distinct  syncrefid
from  refid_list rl
left   join  refdic r  on  rl . refid  =  r . refid
left   join  sync_reference sr  on   (( r . refid  =  sr . dicrefid )   or   ( r . refcode  =  sr . refcode ))
where  r . refid  >   0   and  sr . syncrefid  >   0
2.2. При вызове SYNC_PROFILE_GET_DEFAULT с  recid > 0, rectype = 97 , определять перечень справочников по указанному интеграционному протоколу
Открыть
with  placeid_list  as
(
select   distinct  wd . placeid
from  workplacedocdet wpd
left   join  workplacedoc wd  on  wpd . placeid  =  wd . placeid
where  wpd . rectype  =   97   and   ( wpd . recid  =   cast  (: recid  as  tbigcode )   or   cast  (: recid  as  tbigcode )   is   null  )
)
,  refid_list  as
(
select   distinct  gp . reftodict refid
from  placeid_list p
left   join  workplacedoclinks wpl  on  p . placeid  =  wpl . placeid
left   join  groupsdictlinks gdl  on  wpl . groupid  =  gdl . groupid
left   join  groupsparams gp  on  gdl . codeparams  =  gp . codeparams
where  reftodict  is   not   null
)
select   distinct  syncrefid
from  refid_list rl
left   join  refdic r  on  rl . refid  =  r . refid
left   join  sync_reference sr  on   (( r . refid  =  sr . dicrefid )   or   ( r . refcode  =  sr . refcode ))
where  r . refid  >   0   and  sr . syncrefid  >   0
3. Реализовать форму настройки профилей  ¶
Профили синхронизации справочников
3.1. Кнопки
пп    Наименование    Функция    Комментарий
1  Обновить  Обновить содержимое формы
2  Добавить  Добавить запись в грид профилей
3  Изменить  Изменить наименование выбранного профиля
4  Удалить  Удалить запись из грида профилей
3.2. Фильтры
пп    Наименование    Тип поля    Поле БД    Комментарий
1  Наименование  строка   SYNC_PROFILE.SYNCPROFNAME
3.3. Панель профилей (дерево, на основе SYNC_PROFILE)
пп    Наименование    Тип поля    Поле БД    Комментарий
1  Наименование  строка   SYNC_PROFILE.SYNCPROFNAME   Дерево строить по SYNC_PROFILE.SYNCPROFID, SYNC_PROFILE.PARENT_SYNCPROFID
3.4. Панель настройки профиля
пп    Наименование    Тип поля    Поле БД    Комментарий
1  Наименование  строка   SYNC_PROFILE.SYNCPROFNAME
2  Код  строка   SYNC_PROFILE.SYNCPROFIDENT
3  Хранимая процедура  строка   SYNC_PROFILE.SYNCPROF_SP
4  Код  длинный текст (по  ... )   SYNC_PROFILE.COMMENT
3.5. Панель привязки справочников (на основе SYNC_PROFILE_LINKS)
3.5.1. Кнопки: Добавить, Удалить
3.5.2. Грид (отображать записи по  SYNC_PROFILE_LINKS.SYNCPROFID = SYNC_PROFILE.SYNCPROFID )
пп    Наименование    Тип поля    Поле БД    Комментарий
1  Наименование  строка   SYNC_REFERENCE.REFNAME
2  Код  строка   SYNC_REFERENCE.REFCODE
4. Добавить поддержку параметра для сервиса Sync  ¶
2.1. Добавить поддержку параметра  syncrefprofile_list . При запуске процесса загрузки/обновления справочников:
искать профили, как по числовым идентификаторам ( SYNC_PROFILE.SYNCPROFID ), так и по кодам ( SYNC_PROFILE.SYNCPROFIDENT )
производить загрузку/обновление справочников как по самим указанным профилям, так и по дочерним (по  SYNC_PROFILE.PARENT_SYNCPROFID ). Обновляемые справочники определять по:
результату (набору SYNCREFID) вызова хранимой процедуры ( SYNC_PROFILE.SYNCPROF_SP )
вручную добавленным справочникам (SYNC_PROFILE_LINKS)

Я предоставила ссылку на справочники, которые используются в СЭМД.
Вы курировали этот процесс, когда он запускался и стоял вопрос централизованной загрузки справочников. Решение было - грузить через syncmeneger. Процесс за почти уже два года не изменился:
Клиника покупает СЭМД, для настройки СЭМДа надо загрузить справочники из перечня выше (приведен в теле задачи).
Менеджер настраивает загрузку справочников: единоразово прощелкивает в менеджере синхронизации либо настраивает задачу, чтобы справочники постоянно актуализировались.
Потому что на стороне ФНСИ ряд справочников обновляется постоянно, и в случае расхождения значений между БД, из которой передаем, и ФНСИ, СЭМД может получить ошибку.
Дополнения к описанию процесса:
Состав справочника определяется инструкцией к сэмду, которую заказала клиника.
То есть менеджер берет инструкцию для нужного сэмда, открывает ее, видит список из н-справочников.
Начинает это грузить.
Делает, чаще всего, это единоразово.
Но проблема единоразовой загрузки в том, что чудесным утром фнси решает, что надо в одном справочнике поменять формулировки. И было у нас "возбудитель инфекции не обнаружен", а на следующий день стало "не обнаружено".
И все, сэмд падает в ошибку, клиника звонит менеджеру, тот обновляет справочник, с горем пополам найдя какой требуется.
Либо он поступает умно и делает в sync server задачу и справочник обновляется автоматически.
Но вот клиника говорит, хочу сэмд такой то. И ему надо руками прописывать все эти оиды новых справочников через запятую, а их может быть много. 30-40 штук, для больших сэмдов не предел.
И вот так каждую итерацию надо добавлять руками оиды в загрузчик
