# Чек-лист проверки

Проверки выполняют на центральной базе данных и в филиалах, где подписываются документы. Укажите в протоколе проверки версию МИС, филиал, дату и исполнителя.

## Базовые действия перед проверкой

Перед настройкой интеграции и при возникновении ошибки обновите федеральные сервисы и справочники:

<InitialPreparation />

После выполнения этих действий переходите к проверке готовности или повторите проверку, относящуюся к ошибке.

В пункте **Конфигурация базы данных** выполните [SQL-скрипт проверки конфигурации](/trunk/egisz/diagnostics/sql-configuration-check) и учтите его ограничения.

| Что проверить | Критерий |
|---|---|
| Подключение к порталу | Проверка сервиса данных виртуального сайта в личном кабинете завершается успешно |
| OpenVPN ГОСТ | С компьютера службы репликации доступен IPS proxy service |
| Реквизиты | Организация, финподразделение и сотрудники сверены с ФРМО и ФРМР |
| Параметры | Адреса callback, код РМИС и UUID соответствуют [настройкам](../settings/integration-parameters.mdx) |
| Подпись | Криптопровайдер доступен; сертификат врача действующий |
| Медиа-базы | Настроены для центральной базы данных и каждого филиала |
| НСИ | Выполнена [проверка синхронизации](../../sync_manager/check.mdx): требуемые справочники загружены, обработаны и доступны в МИС |
| Службы | Выполнена [проверка репликатора](../../services1/replic/check.mdx); состояние SyncServer или результат запуска SyncManager проверены по используемой схеме |
| Конфигурация базы данных | Выполнен [SQL-скрипт проверки конфигурации](/trunk/egisz/diagnostics/sql-configuration-check), учтены его ограничения |

## Если проверка не пройдена

Зафиксируйте несоответствие, устраните причину и повторите соответствующую проверку.

Отсутствие ошибок в запросе не подтверждает готовность всей интеграции: запрос может не вернуть строки по отсутствующим сущностям и не проверяет фактическую доставку.

После ручных и автоматических проверок выполните [тестовую отправку СЭМД](../connection/test-integration.mdx).
