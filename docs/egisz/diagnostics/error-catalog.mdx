# Каталог ошибок

Полный перечень кодов ошибок РЭМД Минздрав публикует в справочнике НСИ «РЭМД. Классификатор кодов сообщений» (OID `1.2.643.5.1.13.13.99.2.305`, `https://nsi.rosminzdrav.ru/#!/refbook/1.2.643.5.1.13.13.99.2.305`) в формате `[Код ошибки]:[Описание ошибки]`. Коды статусов передачи в МИС приведены в [статусах передачи](../operation/statuses.mdx). В таблицах приведены типовые ошибки регистрации СЭМД из «Регламента описывающего ФЛК в РЭМД» и первое действие для их разбора. Учитывайте статус и полный текст ответа конкретного документа.

## Этап 1: проверка запроса на регистрацию

Ошибки этого этапа приходят в синхронном (грубая проверка структуры) или асинхронном ответе метода `registerDocument` (полная проверка); запрос файла СЭМД на этом этапе ещё не выполняется.

| Код ошибки | Причина | С чего начать |
|---|---|---|
| `NO_RMIS` | ИС не зарегистрирована в РЭМД | Проверить подключение ИС к РЭМД и правильность её идентификатора в запросе |
| `DISABLED_RMIS` | ИС зарегистрирована, но не активна | Проверить почту ответственного лица на уведомление об отключении и выполнить переподключение |
| `CAN_NOT_ASSOCIATE` | Недопустимая связь документов в запросе | Проверить корректность формирования секции `association` |
| `NOT_UNIQUE_ASSOCIATION` | Связываемая пара документов уже связана | Проверить, не создана ли связь ранее |
| `NOT_UNIQUE_PROVIDED_ID` | Локальный идентификатор документа уже использован | Проверить, не зарегистрирован ли документ ранее, и уникальность идентификаторов в МИС |
| `WRONG_CREATION_DATE` | Дата создания документа позже даты регистрации | Проверить корректность даты создания СЭМД |
| `CANT_BUILD_CERT_CHAIN_TO_ACCREDITED_CA_CERT` | Не удалось построить цепочку сертификата до аккредитованного УЦ | Проверить, аккредитованным ли УЦ выдан сертификат |
| `DOC_DATE_MISMATCH_CERT_NOT_AFTER` / `DOC_DATE_MISMATCH_CERT_NOT_BEFORE` | Документ создан вне срока действия сертификата подписи | Проверить действительность подписи на момент создания документа |
| `NO_END_ENTITY_CERTIFICATE` | В подписи отсутствует сертификат | Проверить наличие сертификата в подписи |
| `NO_SIGNATURE` | В запросе отсутствуют подписи | Добавить подпись в запрос на регистрацию |
| `SIGNATURE_DUPLICATION` | В запросе есть дублирующиеся подписи | Убрать лишние подписи |
| `MULTIPLE_SIGNERS` | В контейнере подписи указано более одного подписанта | Укажите одну подпись одного подписанта |
| `SIGNATURE_DECODING_ERROR`, `UNKNOWN_ALGORITHM`, `WRONG_SIGNATURE_FORMAT` | Техническая ошибка формирования подписи | Проверить формирование ЭП программным обеспечением рабочего места |
| `VALUE_MISMATCH_METADATA_AND_CERTIFICATE` | Сведения в открепленной подписи противоречат запросу | Сверить данные врача и МО в запросе со сведениями подписи |
| `PERSON_NOT_FOUND` / `PERSON_CARD_NOT_FOUND` | Врач не найден в ФРМР или у него нет личного дела | Проверить актуальность сведений о враче в ФРМР |
| `VALUE_MISMATCH_METADATA_AND_FRMR` / `PERSON_POST_IN_FRMR_MISMATCH` | Данные или должность врача не совпадают со сведениями ФРМР | Сверить и актуализировать сведения в ФРМР |
| `ORG_NOT_FOUND_IN_FRMO` | МО не найдена в ФРМО | Проверить сведения о МО в ФРМО |
| `POSITION_TO_ROLE_MISMATCH`, `NO_SPECIALITY`, `NO_ROLE_POLICY_ON_DATE` | Роль, должность или специальность не соответствуют справочнику подписей или виду документа | Сверить со справочником «РЭМД. Правила подписи ЭМД» (OID `1.2.643.5.1.13.13.99.2.42`) |
| `NO_DOCUMENT_KIND_ON_DATE` | На дату регистрации вид документа недопустим (ещё не введён или уже выведен) | Проверить актуальность вида СЭМД на дату регистрации |
| `NO_SNILS` | Отсутствует обязательный СНИЛС пациента | Указать СНИЛС; для отдельных видов документа проверить условия исключения (возраст пациента, иностранный ДУЛ) |
| `PATIENT_MPI_MISMATCH` | Данные пациента по локальному идентификатору отличаются от ранее переданных | Проверить уникальность локального идентификатора пациента и корректность его данных |

## Этап 2: проверка файла СЭМД

Ошибки этого этапа возникают после запроса файла методом `getDocumentFile`; большинство представлено кодом `VALIDATION_ERROR` с текстом, указывающим конкретный элемент.

| Код ошибки | Причина | С чего начать |
|---|---|---|
| `GET_DOCUMENT_FILE_ERROR` | Контрольная сумма полученного файла не совпадает с заявленной в запросе | Проверить, что ИС передаёт именно тот файл, чьи подпись и контрольная сумма указаны в запросе |
| `VALIDATION_ERROR` (кросс-валидация) | Сведения о документе, пациенте, МО, структурном подразделении или враче в файле СЭМД расходятся с запросом на регистрацию | Прочитайте текст ошибки и сверьте формирование запроса с содержимым СЭМД |
| `VALIDATION_ERROR` (справочные значения) | В СЭМД использован справочник или его версия, отсутствующие в ФНСИ | Проверить используемый OID справочника и его версию |
| ошибка по XSD-схеме (например, `cvc-complex-type.2.4.a`) | Грубое нарушение структуры СЭМД | Сверьте структуру документа с руководством по реализации |
| ошибка схематрона | Нарушение конкретных правил вида документа (обязательный элемент, `@nullFlavor`, структура адреса, связанные документы) | Свериться с руководством по реализации нужного вида и редакции СЭМД |

Продолжите [диагностику передачи](/trunk/egisz/diagnostics).
