# Диагностика

Начните с конкретного документа и контура обмена. Для массовой проблемы дополнительно зафиксируйте количество затронутых документов, филиалы и время начала. Эти сведения нужны, чтобы связать ошибку с этапом обмена и результатами предыдущих проверок.

## Подготовка к диагностике

Перед настройкой интеграции и при возникновении ошибки обновите федеральные сервисы и справочники:

После обновления повторите проверку. Если ошибка сохранилась, переходите к диагностике ниже.

## Порядок диагностики

1. В **Журналы → Протоколы ИБ** найдите протокол и запишите его идентификатор, дату, текущий статус и текст ошибки.
2. Определите контур: [РЭМД или ИЭМК](../operation/statuses.mdx). Проверьте, получен ли асинхронный результат.
3. Для ошибки формирования проверьте реквизиты, состав протокола и подпись. Для ошибки внешней проверки сохраните полный текст ответа и его код. Сопоставьте результат с [каталогом ошибок](/trunk/egisz/diagnostics/error-catalog).
4. Выполните относящиеся к ошибке пункты [чек-листа проверки готовности](/trunk/egisz/diagnostics/check-list) и запустите [SQL-скрипт проверки конфигурации](/trunk/egisz/diagnostics/sql-configuration-check), учитывая его ограничения.
5. После устранения причины повторите запрос в соответствии с состоянием документа и зафиксируйте новый статус и текст ответа.

Не изменяйте статусы в БД по общей инструкции: возможность повторной отправки зависит от состояния документа и результата предыдущей регистрации.

## Быстрый переход по симптому

| Симптом | Куда перейти |
|---|---|
| Ошибка при формировании, до запроса на регистрацию | [Каталог ошибок, этап 1](/trunk/egisz/diagnostics/error-catalog#этап-1-проверка-запроса-на-регистрацию) |
| Файл СЭМД отклонён после запроса на регистрацию (`VALIDATION_ERROR`, ошибка схемы) | [Каталог ошибок, этап 2](/trunk/egisz/diagnostics/error-catalog#этап-2-проверка-файла-сэмд) |
| Документ завис в статусе «Получен синхронный ответ» | [Статусы передачи, время ожидания](../operation/statuses.mdx#время-ожидания) |
| Статус обработки документа в МИС не изменился | [Статусы обмена](../operation/statuses.mdx) |
| Нужно переотправить документ | [Переотправка документов](/trunk/egisz/operation/resend) |
| Пациент отказывается от передачи данных в ЕГИСЗ | [Отказ пациента](../operation/patient-refusal.mdx) |
| Справочник загружен, но значения нет в МИС | [Проверка синхронизации и НСИ](../../sync_manager/check.mdx#downloaded-not-visible) |
| Задержка обмена в филиальной сети | [Проверка репликатора](../../services1/replic/check.mdx) |
| Проблема началась после обновления МИС | [Журнал и результат обновления](../../services1/cp-upgrader/check.mdx) |
| Расхождение реквизитов МО, подразделения или сотрудника | [Поддержание данных](../operation/data-maintenance.mdx) |

Если симптом не описан в таблице, выполните общий порядок диагностики и зафиксируйте результаты всех проверок.

## Проверка служебных модулей

- При задержке обмена выполните [проверку работы репликатора](../../services1/replic/check.mdx) и OpenVPN ГОСТ.
- При отсутствии или устаревании справочников выполните [проверку синхронизации и НСИ](../../sync_manager/check.mdx).
- Если проблема возникла после обновления, проверьте [журнал и результат обновления](../../services1/cp-upgrader/check.mdx).

## Результат диагностики

Зафиксируйте версию МИС, юридическое лицо и филиал, контур, вид и редакцию СЭМД, время проверки, статус, текст ошибки, выполненные действия и результат повторной передачи. Если причина не установлена или ошибка сохраняется, подготовьте [обращение в поддержку](/trunk/egisz/diagnostics/support-request).
