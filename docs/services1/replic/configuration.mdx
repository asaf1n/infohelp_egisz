# Задачи и конфигурация репликации

В ReplConf задача определяет выполняемую процедуру и её конфигурацию. Задачи работают с группами объектов. Текстовый идентификатор используется для управления задачей и ссылок из других задач.

## Проверка настроек

1. Откройте **Настройки → Задачи репликации**.
2. Найдите задачу по идентификатору и проверьте принадлежность группе.
3. Сопоставьте тип задачи и её конфигурационный текст с эталоном поддерживаемой версии.
4. Проверьте исходные и целевые группы, их состав и параметры подключения к базам. В конфигурации как базы могут быть представлены и точки веб- или FTP-обмена.
5. Проверьте признак **Не используется**: включённый признак запрещает выполнение задачи сервером.
6. Зафиксируйте расписание и зависимости из действующей конфигурации и сверьте их с эталоном используемой версии.

Кнопки **Запуск**, **Перезапуск**, **Завершение** передают команду серверу через консоль. Они действуют на выбранную задачу или группу; до применения проверьте выбранный объект. Для диагностики сначала сохраните журналы и текущее состояние.

## Обновление справочника таблиц по эталонной базе replconf

Основной способ актуализации настроек репликации в клинике — обновление справочника таблиц на основании эталонной базы `replconf`. Автоматизированное обновление возможно только для баз `replconf`, созданных на основании эталонной: записи сопоставляются по идентификаторам. Собственные группы репликации, добавленные в клинике, таким способом не обновляются.

В процедуре участвуют три вида баз: эталонная база `replconf` (локальная копия из репозитория), база `replconf` клиента, настройки которой актуализируются, и базы МИС (ЦБД и филиалов), в которых создаются триггеры репликации.

1. Обновите локальную копию эталонной базы `replconf` из репозитория: `sds-documents\Внешние\Внедрение\Модули\Система управления сетью филиалов\repl\data\replconf.7z`.
2. Сохраните резервную копию базы `replconf` клиента.
3. В эталонной базе выполните запрос:

   ```sql
   select * from repl_export_tables
   ```

   Результат представляет собой набор SQL-запросов для актуализации базы клиента. Скопируйте его в буфер обмена или файл.
4. Выполните полученные запросы на базе `replconf` клиента. Рекомендуемый инструмент — `BkUtils3`, раздел `Скрипты`.
5. Определите таблицы без триггеров репликации. В мастере настройки репликации сначала добавьте все таблицы выбранной группы, затем выберите `Действия` → `Исключить таблицы с триггерами репликации`. В списке останутся таблицы, на которых необходимо создать триггеры.
6. Создайте недостающие триггеры репликации: на таблицах с оперативной информацией — в базах филиалов, на таблицах со справочной информацией — в ЦБД.

После обновления справочника таблиц сверьте расписания и зависимости задач с эталонной конфигурацией по разделу [«Проверка настроек»](#проверка-настроек).

## Проверка данных

Контрольные суммы используют для сравнения результатов агрегатных запросов в двух БД. Сравнение охватывает только данные, выбранные запросом. Результаты выполнения скриптов проверяйте в соответствующем журнале.

Проверку выполнения проводите по [инструкции контроля репликатора](./check.mdx). Для интеграции сопоставьте идентификаторы с [задачами ЕГИСЗ](../../egisz/settings/replication.mdx).
