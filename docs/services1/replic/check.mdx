# Проверка работы репликатора

Выполняйте проверку после настройки, обновления МИС и при задержке обмена. Потребуются доступ к состоянию службы, ReplConf и журналам нужного периода. Для проверки не нужно изменять БД или принудительно повторять задачи.

## Порядок проверки

1. Зафиксируйте сервер, версию ReplServer, базу конфигурации, период и идентификаторы проверяемых задач. Для ЕГИСЗ выберите их из [перечня задач](../../egisz/settings/replication.mdx).
2. Средствами ОС проверьте состояние установленной службы или демона и путь к исполняемому файлу. Состояние «Работает» подтверждает запуск процесса, но ещё не выполнение обмена.
3. В ReplConf откройте консоль через **Файл** или **F9**. Если подключиться не удалось, сохраните ошибку и проверьте сервер, адрес и доступность административного порта.
4. В **Настройки → Задачи репликации** сверьте [конфигурацию и признак использования](./configuration.mdx). Не перезапускайте всю группу для проверки одной задачи.
5. Откройте журнал, соответствующий типу задачи. Задайте период, задачу, исходную и целевую группы, затем нажмите **Обновить**. Пустая выборка требует проверки фильтров и расписания.
6. Для задач типа `repl` проверьте в **Журнале репликации** время начала и окончания, статус, текст ошибки, **Обработано записей** и **Осталось записей**. Сравните несколько последовательных выполнений.
7. Сверьте результат с данными получателя. Для ЕГИСЗ выполните [тестовую передачу](../../egisz/connection/test-integration.mdx): проследите отправку, ответ и изменение статуса документа.

## Оценка результата

| Наблюдение | Следующий шаг |
|---|---|
| Служба остановлена | Зафиксировать состояние и системное событие; определить причину до запуска |
| Служба запущена, консоль недоступна | Проверить административное подключение и сетевой доступ |
| Нет выполнений в ожидаемый период | Проверить фильтры, расписание, признак использования и зависимости |
| Выполнение завершилось ошибкой | Сохранить текст ошибки, идентификатор задачи и параметры выполнения; определить причину |
| Остаток растёт между выполнениями | Сопоставить поступление изменений и обработку; проверить ошибки и доступность получателя |
| Обработано ноль записей | Установить, были ли подходящие изменения; ноль сам по себе не означает сбой |
| Задача успешна, ответ ЕГИСЗ не получен | Проверить [callback и параметры обмена](../../egisz/settings/integration-parameters.mdx), продолжить трассировку документа |

Проверка завершена, когда нужные задачи выполняются по расписанию, причины ошибок установлены, объём необработанных записей соответствует регламенту, а контрольные данные переданы получателю. Допустимую задержку обмена сверяйте с регламентом контура.

Для [обращения в поддержку](/trunk/egisz/diagnostics/support-request) приложите сервер и версию, идентификатор задачи, источник и получатель, время с часовым поясом, фильтры журнала, результат, текст ошибки и обезличенный идентификатор контрольного документа.
