# Проверка результата обновления

Проверяйте каждую целевую БД отдельно: журнал хранится в самой базе.

1. Откройте **Журнал** из базового мастера либо журнал обновлений через меню **Сервис** в Pro. Кнопкой **Открыть** выберите нужную БД.
2. Задайте период работ: по умолчанию показаны текущие сутки. Нажмите **Обновить**.
3. Проверьте целевую БД, версию, ревизию, коды и статусы обновлений. Для проблемной строки изучите панели **Скрипт**, **Условия**, **Ошибка**.
4. Проверьте **Показать невыполненные**. Разберите ошибочные и пропущенные обновления; пропуск по условию оценивается по применимости скрипта к базе.
5. Сохраните результат через **Экспорт**, если он нужен для протокола. Отдельно зафиксируйте случаи **Отложить**: они могут отсутствовать в журнале.
6. Откройте МИС нужной версии и выполните согласованные контрольные сценарии. Для интеграции ЕГИСЗ проверьте [репликатор](../replic/check.mdx), [синхронизацию](../../sync_manager/check.mdx) и [тестовую передачу](../../egisz/connection/test-integration.mdx).

## Критерий завершения

Версия и ревизия каждой базы соответствуют плану; все предназначенные для неё обновления применены либо имеют объяснённое неприменимое условие; необработанных ошибок нет; контрольные сценарии завершены. Для замечаний указаны ответственный и решение.

Протокол: дата и время, исполнитель, база и филиал, версии до и после, ревизия, резервная копия, результат журнала, контрольные сценарии и отклонения.
