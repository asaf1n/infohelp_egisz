# Автоматическая синхронизация

SyncServer выполняет фоновую синхронизацию как служба Windows. SyncManager также поддерживает разовый запуск из командной строки. Выберите используемый в контуре способ и проверяйте его конфигурацию и журнал.

## Подготовка SyncServer

Работы выполняет администратор сервера совместно со специалистом МИС. До установки службы нужны подготовленное подключение к БД, пользователь службы в МИС, доступ к ФНСИ, настроенные справочники и рабочие каталоги. Для филиальной сети загрузка НСИ выполняется на ЦБД.

В примерах МИС установлена в `\Infoclinica`, а файлы службы размещены в `\Infoclinica\Services\Sync`. Замените пути на каталоги вашей установки. Для службы нужны `SyncServer.exe`, `sync.conf` и библиотеки согласованного комплекта поставки.

Используйте шаблон `Services\Sync\Win64\sync_template.conf` из соответствующей поставки. Версию `SyncServer.exe` проверяйте в свойствах файла.

## Параметры sync.conf

Полный список параметров, их назначение и правила расписания вынесены в отдельный [справочник параметров sync.conf](./reference.mdx). Ниже приведён только порядок их применения при настройке службы.

До перехода к автоматической работе проверьте время сервера, первый цикл после старта и выполнение в заданное время. Поведение при пропущенном запуске и длительной операции требует проверки для установленной версии.

### Порядок настройки {#configuration-steps}

1. Сохраните резервную копию текущего `sync.conf` и зафиксируйте версию EXE. Изменяйте существующий файл либо создавайте его из шаблона той же поставки, если файла ещё нет. Сохраняйте кодировку файла; шаблон для указанного компонента использует Windows-1251.
2. Сверьте `a` с записью `infodent.ini`, проверьте `uid` и доступ к выбранной БД. Назначение параметров — в [справочнике](./reference.mdx#configuration).
3. Задайте согласованный состав в `syncrefcode` или `syncprofiles`. Полный список НСИ из другого контура не является универсальным комплектом для всех СЭМД.
4. Настройте `logpath`. Каталог файлов справочников проверьте отдельно в [настройках справочников](./settings.mdx); `logpath` не задаёт папку загрузки.
5. Настройте расписание (`SyncTime` или `syncinterval`, см. [справочник](./reference.mdx#расписание)) и доступ к источнику от имени учётной записи службы. Убедитесь, что учётная запись Windows имеет доступ к нужным каталогам.
6. Примените конфигурацию по порядку эксплуатации компонента. Применение изменений без перезапуска не подтверждено для указанного компонента. Для уже работающей службы согласуйте окно перезапуска и проверьте завершение активного цикла.
7. После запуска сверяйте журнал и [результат синхронизации](./check.mdx): правильный псевдоним, прочитанный состав, выполнение загрузки и обработки.

## Установка и проверка службы Windows

Команда установки требует проверки для выбранного комплекта поставки. Выполняйте её только при отсутствии службы.

1. В оснастке **Службы** (`services.msc`) найдите **Infoclinica SyncServer**. Если она уже установлена, сверьте путь и настройки; повторная установка не требуется.
2. Если службы нет и комплект подготовлен, откройте PowerShell с правами администратора и выполните:

   ```powershell
   Set-Location -LiteralPath '\Infoclinica\Services\Sync'
   .\syncserver.exe -install
   ```

3. Обновите список служб и откройте свойства **Infoclinica SyncServer**. В примере путь к исполняемому файлу: `\Infoclinica\Services\Sync\SyncServer.exe /svc`. Сверьте зарегистрированный путь со своим каталогом установки.
4. На вкладке **Вход в систему** проверьте учётную запись и необходимые доступы. Выбирайте учётную запись по требованиям доступа к БД, сети и каталогам.
5. Для автоматической работы установите тип запуска **Автоматически**, запустите службу и проверьте состояние **Выполняется**.
6. Проверьте журнал и выполнение в установленное время. Тип запуска Windows определяет запуск службы, а расписание загрузки НСИ задаётся в `sync.conf`.

[![Свойства Infoclinica SyncServer: исполняемый файл, автоматический запуск, состояние Выполняется](/img/sync-manager/service.png)](/img/sync-manager/service.png)

Проверить состояние без изменения настроек можно командой:

```powershell
Get-CimInstance Win32_Service -Filter "Name = 'Infoclinica SyncServer'" |
    Select-Object Name, State, StartMode, PathName, StartName
```

### Запуск как приложение {#application-mode}

Пункт **SyncServer as App** в стартовом окне запускает `SyncServer.exe -app -debug`. Режим предназначен для диагностики специалистом. Перед запуском проверьте действующие процессы и порядок выбора конфигурации для установленной версии. Совместная работа со службой для одной БД не подтверждена; второй экземпляр запускайте только по согласованной процедуре диагностики.

## Журнал службы

Откройте журнал в каталоге `logpath`. Сверьте псевдоним БД, путь журнала, списки кодов справочников и профилей, расписание, начало и результат инициализации.

Сообщения **Инициализация БД завершена успешно** и **Инициализация и загрузка задач завершена** подтверждают запуск компонента. Для проверки синхронизации найдите результат загрузки и обработки конкретного справочника. Порядок ротации и хранения журнала уточните для установленной версии.

## SyncManager через командную строку

Параметр `-e` принимает значения `SYNC_REFERENCE.REFCODE` через запятую. Пример выбора трёх справочников:

```text
SyncManager.exe -e "V002,V003,V004"
```

Замените список кодов на согласованный состав загрузки. Пустой список прерывает операцию. Если код принадлежит группе, загрузка охватывает её вложенные справочники.

По умолчанию журнал `SyncManager.log` размещается рядом с приложением. Параметр `-logfile` задаёт другое расположение журнала. Проверьте права учётной записи запуска на соответствующий каталог.

SyncManager сначала загружает данные. Если загрузка завершилась без ошибок, запускается обработка последних версий. Для внешней системы **16 «Синхронизация справочников»** требуется заполненное поле `PUID`.

Зафиксируйте расписание, учётную запись и условия повторного запуска в регламенте эксплуатации.

Для обоих вариантов выполните [проверку фактической загрузки и обработки](./check.mdx).

Перед вводом в эксплуатацию проверьте загрузку по расписанию, повторный запуск после ошибки и загрузку по профилю на тестовой БД.
