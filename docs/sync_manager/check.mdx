# Проверка службы синхронизации и НСИ

Проверка включает запуск компонента, выполнение загрузки, обработку и доступность данных в МИС. Для ЕГИСЗ её выполняют на центральной БД и проверяют распространение данных в нужные филиалы по принятой схеме.

## Порядок проверки

1. Зафиксируйте сервер, БД, версию компонента, способ запуска и проверяемый код справочника либо профиль.
2. Для SyncServer найдите службу **Infoclinica SyncServer**, сверьте путь к исполняемому файлу, состояние и учётную запись. Сопоставьте `a` в `sync.conf` с секцией `infodent.ini` и строкой **Алиас БД** журнала. Назначение параметров описано в [справочнике параметров sync.conf](./reference.mdx#configuration).
3. Для SyncManager проверьте команду и результат последнего запуска в используемом планировщике. Разовый процесс после завершения может отсутствовать. Проверяйте результат его выполнения по журналу.
4. Проверьте соответствие состава загрузки [требованиям НСИ](../egisz/settings/nsi.mdx), расписание, доступ к источнику и права на рабочие каталоги.
5. Откройте журнал за ожидаемое время выполнения. Для SyncManager используется `SyncManager.log` либо путь из `-logfile`. Для SyncServer каталог задаёт `logpath`. Сопоставьте время, БД, код справочника, результат загрузки и обработки.
6. В **Справочники → Настройка справочников** проверьте текущую и загруженные версии. Сопоставьте их с версией, требуемой подключаемым видом СЭМД.
7. Убедитесь, что нужная версия обработана и контрольное значение доступно в соответствующем поле МИС. При филиальной схеме проверьте тот же результат в целевом филиале.

## Справочник загружен, но не появился в БД или МИС {#downloaded-not-visible}

Сначала установите, какой результат уже есть: скачанный файл, версия в менеджере, строки в таблице справочника или значение в пользовательском поле. Это разные контрольные точки.

| Контрольная точка | Что проверить | Действие по результату |
|---|---|---|
| Целевая БД | Подключение в `infodent.ini`, поле **Целевая** мастера, `a` и **Алиас БД** журнала службы | Если подключение не соответствует заданию, прекратить повторные загрузки и уточнить цель |
| Получен только файл | Завершение загрузки, нужный OID, ошибки доступа к файлу, наличие версии в нижней части формы справочника | По ошибке устранить доступ или настройку источника; после этого повторить загрузку выбранного справочника |
| Версия и строки видны в менеджере | Выбранную версию и результат обработки, поле **Обработчик** | Выполнить [обработку](./synchronization.mdx); отсутствующий обработчик сверить с настройкой этого справочника |
| Ожидались данные в определённой таблице | Поле **Таблица** в настройках и назначение обработчика | Проверять указанную таблицу и версию; если схема неизвестна, передать разработчику код, таблицу и журнал вместо произвольной правки данных |
| Обработка завершена, значение в МИС отсутствует | БД, версию и конкретное поле МИС, настройки использования справочника и требуемые сопоставления | Зафиксировать контрольное значение и ожидаемое поле; передать на проверку настройку МИС |
| Значение есть в ЦБД, отсутствует в филиале | Состав и результат распространения справочника | Проверить [репликацию](../services1/replic/check.mdx) и повторить контроль в целевом филиале |

Пример чтения контрольных точек: на [снимке настроек](./settings.mdx) указаны `NSI_ROUTEINFECTION` и версия `2.1`, внизу видны строки. Строки подтверждают загрузку данных в менеджер. Выполнение обработчика и доступность значения в МИС проверяйте отдельно.

Не используйте удаление версии, очистку таблиц и прямые `INSERT` как универсальное исправление. Такие действия требуют подтверждённой схемы и отдельной процедуры восстановления.

## Другие отклонения

| Наблюдение | Что проверить |
|---|---|
| Нет записей о запуске | Расписание, конфигурацию, путь журнала и права записи |
| Служба работает, есть только инициализация | Ожидаемое время по `SyncTime`, фактическое время сервера, последующие записи о конкретных справочниках; старт службы ещё не подтверждает цикл |
| В журнале интервал равен нулю | Значение `SyncTime`: при заданном времени `syncinterval` игнорируется |
| Вручную загрузка работает, через службу не выполняется | Совпадение подключения и состава, пользователя `uid`, учётную запись Windows, доступ к сети и каталогам от имени учётной записи службы |
| Ошибка доступа к источнику | Адрес, реквизиты авторизации и сеть от имени учётной записи запуска |
| Файлы загружены, значений в МИС нет | [Обработку справочника](./synchronization.mdx), обработчик и выбранную версию |
| Нужного справочника нет в выполнении | Код, состав группы или профиля, признаки отключения |
| Профиль есть, но его состав не выполняется | Сохранённый код или ID в `syncprofiles`, целевую БД, дату отключения, строки состава и результат процедуры профиля |
| Зелёная отметка, но операция ещё идёт | Нижнюю строку состояния и окончательный результат; экран **Перед получением версии справочника** не является итоговым |
| В ЦБД данные есть, в филиале отсутствуют | Схему распространения и [результат репликации](../services1/replic/check.mdx) |

Проверка пройдена, если для требуемых справочников подтверждены загрузка, обработка и доступность значений в нужной БД. Ожидаемую версию определяют требования интеграции; произвольная установка самой новой версии не заменяет эту сверку.

Сохраните протокол: компонент и версия, сервер и БД, время с часовым поясом, код или профиль, ожидаемая и фактическая версии, журнал, контрольное значение и результат в филиале. Если причина не установлена, подготовьте [обращение в поддержку](/trunk/egisz/diagnostics/support-request).
