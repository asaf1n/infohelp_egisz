# Контракт репозитория InfoHelp

Always-on контракт для агента при работе с материалами руководства по интеграции (Docusaurus).
Один факт — один источник истины (SSOT). Ссылайся на авторитетный документ вместо смыслового дублирования.
История изменений, альтернативы и обсуждения не добавляют обязательных требований без явного согласования.

## 1. Маршрутизация контекста (Documentation Routing)

Перед началом работы обратись к соответствующему авторитетному источнику:

| Затрагиваемая область | Обязательный документ (SSOT) | Каноническая проверка |
|---|---|---|
| Стандарты стиля, структура страниц, редполитика | `source/DOCUMENTATION_STANDARD.md` | Сверка с правилами стиля |
| Пользовательская документация «Интеграция с ЕГИСЗ» | `docs/egisz/` | `npm run build` (проверка ссылок и якорей) |
| Служебные модули (обновления, репликация) | `docs/services1/`, `source/SERVICE_MODULES-2026-09-12.md` | `npm run build` |
| Загрузка и синхронизация справочников (SyncManager) | `docs/sync_manager/`, `source/SYNC_MANAGER-2026-09-12.md` | `npm run build` |
| Внутренние материалы и регламенты ЛТП | `internal/egisz/` | `npm run build` |
| Карта нормативных источников МЗ РФ и противоречий | `source/ONLINE_SOURCES.md`, `source/EGISZ_REGISTRIES-2026-09-12.md` | Сверка с первоисточниками |
| Версионированные снимки руководства | `versioned_docs/` | Не правятся без явного поручения |

## 2. Инварианты материалов
- **Сохранение фактуры**: Не удаляй технические детали, OID, имена настроек и ограничения ради «краткости». Не объединяй и не разделяй страницы без оснований в исходных материалах.
- **Идемпотентность и целостность**: При переносе или переименовании страниц синхронно обновляй все входящие ссылки, меню и якоря.

## 3. Требования к стилю и содержанию (Редполитика)
- **Связность и полнота**: Пиши полными предложениями, связывая действие с причиной и результатом. Не используй телеграфный стиль и пустые словесные связки.
- **Структура процедур**: Назначение и применимость → условия → нумерованные шаги (место, действие, ожидаемый признак) → следующий шаг при отклонении.
- **Точность данных**: Сохраняй точные наименования интерфейса, полей, команд, OID, таблиц и статусов. Редактура не должна искажать фактический смысл.
- **Единый источник**: Не дублируй одну и ту же инструкцию между страницами — оставляй её в базовом разделе и давай ссылку.

## 4. Канонические команды проверки и DoD
Проверки без зависимости от работающего стенда предпочтительно выполнять в собственной песочнице с зависимостями проекта. `docker compose exec` использует общий контейнер и не изолируется отдельным worktree; изменения этого контура выполняются последовательно. Сборка в песочнице не подтверждает визуальное состояние стенда.
- **Проверка типов (TypeScript / Docusaurus):**
  `docker compose exec -T infohelp_egisz npm run typecheck`
- **Проверка сборки, целостности ссылок и якорей (DoD):**
  `npm run build` (два прогона при обновлении конфигурации или плагинов).
- **Визуальная проверка**: Dev-стенд на `http://localhost:3006` (скрипт `.\start.ps1 -NoPause`).
- **Отчёт DoD**: перечень изменённых страниц, результат `npm run build`, непроверенные внешние ссылки (если есть) и открытые риски.
